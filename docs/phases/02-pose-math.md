# Phase 02 — pose mathematics and deterministic fixtures

**Status:** PLANNED; any bootstrap math is only a starting slice. **Dependencies:** phase 00; phase-01 measurement vocabulary. **Evidence:** none for full phase completion.

## Outcome and boundaries

Create a platform-independent geometric core whose units, frame conventions, interpolation, and invalid-input behavior are explicit. `Sources/SecondShotCore` must import neither ARKit nor AVFoundation. Device adapters perform conversions; synthetic fixtures remain visibly synthetic. This phase proves arithmetic and data handling, never camera accuracy.

Use the [capture and coordinate contract](../architecture/capture-and-coordinates.md) as the normative representation. Proposed source names below are implementation targets; inspect existing names before adding overlapping abstractions.

## Implementation tasks

1. Implement or extend `Vector3`, `Quaternion`, `RigidPose`, `PoseSample`, and `PoseProvenance` value types. Validate finite components, nonzero quaternion norm, nonnegative elapsed time, and a known coordinate convention. Prefer immutable `Sendable` values.
2. Implement normalization, quaternion conjugation/composition, rotation of a vector, and rigid-transform inversion/composition. Document multiplication order with an actual transformed point. A named `referenceFromCamera` pose must not mean the inverse elsewhere.
3. Calculate translation error as Euclidean distance in meters and angular error with the shortest quaternion arc: normalize both inputs, use the absolute quaternion dot product, clamp to the valid inverse-cosine domain, and convert radians to degrees only at presentation boundaries. Equivalent quaternions `q` and `-q` must produce zero error.
4. Add timestamp-bracketed interpolation: linear position plus shortest-path spherical orientation interpolation. Use a stable near-collinear fallback. Reject duplicate/nonmonotonic timestamps at import and do not extrapolate beyond the recorded range without an explicit caller policy.
5. Create small hand-auditable fixtures for identity, a one-meter translation, a 90-degree rotation, an arc, nonuniform frame cadence, and interrupted tracking. Include known answers independent of the implementation, not fixtures generated by the exact function under test.
6. Define explicit tracking validity and origin identifiers in each sample. A missing sample is not a zero pose. Comparing two different origin IDs must return a typed failure until a reviewed coordinate bridge exists.

## Contracts and error behavior

Persist meters, seconds/rational media timestamps, column-major matrices when a matrix is serialized, and quaternion order `x,y,z,w`. UI centimeters must never be written back as meters. Keep pose-estimation error, temporal error, and tracking validity separate; no invented universal “accuracy percentage.” Internally estimated geometric deviation does not establish ground-truth physical precision.

Set deterministic numeric tolerances appropriate to Double arithmetic, for example `1e-9` for pure-core round trips away from singular cases. These are software tolerances only, not millimeter claims. Malformed values return an error; no NaN propagation or silently normalized zero quaternion.

## Verification

**Core tests:** identity/inverse round trips; noncommutative composition; quaternion sign equivalence; 0/90/180-degree cases; interpolation endpoints and midpoint; zero-length segment; duplicate/descending timestamps; invalid components; mixed origins; and a realistic several-thousand-sample fixture. Run `swift test` and the configured simulator unit-test target.

**Property-style tests:** deterministic seeded rotations preserve vector length; composed inverses recover points; interpolation remains bounded between endpoints. Preserve seeds on failure.

**UI tests:** the synthetic demo formats units correctly and cannot display a normal tracking claim for invalid input. No physical-device evidence is required to complete this arithmetic phase.

## Failure and performance safeguards

Avoid nearest-point-only matching as the future retake algorithm: crossing paths and stationary sections are ambiguous. This phase only supplies interpolation/error primitives. Measure linear scans before adding indices; prefer a small auditable implementation to untested optimization. Reject oversized imported fixture arrays before allocation.
