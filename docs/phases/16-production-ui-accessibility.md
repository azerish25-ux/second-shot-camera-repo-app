# Phase 16 — production interface and accessibility

**Status:** PLANNED. The initial Demo Studio is a foundation, not acceptance evidence for this phase.

## Outcome and dependencies

Turn the capture, guidance and review capabilities into a coherent iPhone experience that is understandable outdoors, one-handed and under production pressure. Read the [design specification](../design/) and [agent instructions](../../AGENTS.md). Depend on phases 03, 10–12 and the phase-15 product-proof decision. Visual prototyping can proceed earlier, but live-capture wording and success states must wait for real capability evidence.

The objective is a dependable creative instrument, not a reskinned social camera. Do not add an editor timeline, social feed, account onboarding, animated mascots or unsupported precision readouts. The graphite/paper-white palette, restrained cyan guide and amber warning states are semantic roles, not permission to sacrifice legibility. Reserve red for recording and stopping.

## Implementation work

1. Consolidate typography, spacing, contrast, touch sizes, surfaces and animation durations in `Sources/SecondShotApp/DesignSystem/`. Resolve semantic light/dark appearances and accessibility variants. Use scalable system text and existing named SF Symbols rather than icon-font codepoints.
2. Complete the entry, library, preparation, reference, relocalization, retake, interruption, comparison and export states. Every screen needs loading, empty, denied, unavailable and recoverable-error behavior where relevant. State comes from the phase-03 model; the view must not independently decide that tracking is valid.
3. Keep Stop reachable without opening a sheet. Place recording controls above the bottom safe area, away from the screen edge and distinct from destructive project deletion. Show elapsed time, selected lens/format and tracking validity without displaying stale telemetry as current.
4. Make the distinction between synthetic demo, supported live capture, unavailable hardware and incomplete features explicit. Screenshots and screenshots generated by CI must carry their true mode. Do not convert an unavailable live session into a plausible-looking synthetic one.
5. Implement a compact guidance hierarchy: one primary correction, optional secondary detail, and a conspicuous pause state. A user should not need to read six rapidly changing numbers while moving. Provide visual alternatives to every sound/haptic signal; disable audible coaching when it would contaminate recorded sound unless the user knowingly enables it.
6. Give controls stable accessibility identifiers for tests and localized spoken labels for people. Decorative paths and thumbnails must not crowd the VoiceOver order. Combine related telemetry into intelligible summaries and throttle spoken changes.

## Verification

Extend `Tests/SecondShotUITests/` with the complete demo journey, permission-denied routes, cancellation, rotation and interruption presentations. Capture actual simulator screenshots at a small and large iPhone size, normal and accessibility text sizes, light/dark appearance and Reduce Motion. Test right-to-left and expanded pseudo-localized strings once phase 19 supplies them. A screenshot existing is not a visual approval; inspect it for clipping and contradictory statuses.

Use the Accessibility Inspector plus hands-on VoiceOver and Voice Control on a real iPhone. Simulator tests do not establish tactile feel, outdoor readability or safe filming. Observe at least five consented target users performing preparation, one retake and export; record task failures rather than coaching people through hidden controls.

## Acceptance and recovery

- All interactive targets are at least 44 by 44 points, including icon-only actions, with no overlapping hit areas.
- Normal text meets a 4.5:1 contrast target and large text 3:1; graphical status indicators have adequate contrast and a non-color explanation. Measure actual composited camera-overlay backgrounds, not only token swatches.
- The critical journey remains usable at the largest supported Dynamic Type sizes without truncated safety/status information. Scrolling is acceptable; shrinking text to fit is not.
- Reduce Motion removes nonessential spatial transitions and retains an intelligible static guide. There is no flashing error animation.
- Initial usability target: four of five pilot users complete the bounded journey unaided. This is a small formative test, not statistical proof or an accuracy claim.

On layout failure, prefer moving secondary telemetry into a disclosure rather than hiding Stop or status. If live audio/haptic feedback worsens capture, ship visual guidance first. Preserve the user's project when leaving any screen.

## Evidence and handoff

Attach screenshot artifacts, tested settings/device identifiers, an accessibility finding log, before/after fixes and anonymized usability observations to the phase report. Commit tests and design-token changes together. Record unresolved accessibility limitations honestly; only claim features in App Store accessibility metadata that were evaluated.
